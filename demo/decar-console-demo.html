Deciding a match

Two sightings are compared only on the evidence they both carry. The score is the percentage of that shared evidence which agreed — so 80% means four-fifths of what could be compared matched, not that the system is 80% sure.

How much of the evidence has to be there · advanced

A high score is cheap when almost nothing could be compared — two sightings that share only a jacket colour can agree 100% and mean nothing. So a match must also clear a minimum for how much of the available appearance evidence was actually usable — the term used in the engine, the config file and the logs for this is coverage. That minimum rises with the gap between the two sightings, because a longer gap makes coincidence more likely.

Saving never overwrites a version. Each save writes a new one and points the engine at it, so every past match can still say which settings produced it — and Make active returns to an earlier version without losing anything in between. Numbers are handed out once, in the order versions are created, and never reused.
A version's real identity is a checksum of its contents, not its number — so returning to settings you have used before lands you back on v2 rather than creating an identical v4. The checksum is on the version number's tooltip, in the audit log, and in diagnostics; it is not something you should have to read.
Turning a factor off is the same as setting its weight to zero: it is not scored, and it is not counted against the evidence available. It is left out entirely.
Factors are named in plain language here; Show config keys reveals the identifiers used in the configuration file, the audit log and support requests (upper_colour, plate).
Basic and Advanced change what is shown, never what is enforced — the rules hidden in Basic are still in force, at whatever values the active version holds.

Normalization map

Connectors

Everything that feeds DeCAR or reasons about what it feeds. A connector is a plug-in: it runs in its own process, speaks a versioned contract, and is trusted only for what it declares.

Each connector is headed by the name you gave it. A connector has two names and they do different jobs. The instance id is the one you chose when you configured it: it is fixed once created, because it is what acknowledgements, credentials and every record this connector produced are attributed to, and it is what appears in logs. The display name is a label you can change whenever you like, and it is shown here with the instance id beside it — never instead of it. A connector with no display name is headed by its instance id, which is not the same thing as being named after it: clearing the name returns it to that state. synth and onprem below are in that state.

Reports — where results go

A capability counts only when both sides implement it. A source may report faces while nothing here consumes them — that pair is listed as declared, not consumed rather than advertised as a working feature.
Contract versions are pinned per connector. A connector speaking an older contract keeps running where the shapes still line up, and says so, rather than being silently trusted or silently dropped.

Cameras

Cameras arrive from their source connector — DeCAR does not talk to hardware. What is set here is what the matcher needs to reason about place: the zone a camera covers, which cameras it adjoins, and where each direction out of frame actually leads.

Places — destinations that are not cameras

Adjacency is one fact per pair and is confirmatory only: it can support a match across two cameras and cannot refuse one. What refuses is the travel window — a crossing faster than physically possible is evidence about the subject, where a camera graph is only a statement about the configuration.
A direction that leads to a camera says the subject should reappear there; one that leads to a place says coverage ends. Those are opposite expectations, and the matcher needs to be told which it is.

First run — create the administrator account

There is no default password and no account until you make one. On its first start the core writes a one-time setup token to setup-token in its data directory, readable only by the account the service runs as — so completing this needs access to the machine DeCAR runs on, not just to this page. The token is deleted the moment setup succeeds.

The administrator is called admin. That is not a choice: an entry in a correction or audit list names whoever made it, so the first administrator’s name and the name the core writes for its own automatic changes both have to mean exactly one thing. You choose the password only.

At least 12 characters. There are no composition rules, nothing is truncated, pasting works, and you will never be asked to rotate it. Type it twice because it cannot be reset from this page — see below.

Lost the administrator password?

There is no password reset on this page, and DeCAR sends no email. That is deliberate: a deployment is expected to have a single administrator, and a reset that anyone able to reach this page could start would be the easiest way in rather than the hardest. Getting back in is a local act — it needs access to the machine DeCAR runs on, the same access first-run setup needs.

The administrator password is the only way in — nothing creates a second account after first-run setup — so it is worth keeping in a password manager.

About this demo

What it is

A single self-contained HTML file showing the DeCAR console: the main sections (Timeline · Detections · Associations · Watchlists · Review) and Settings (Policies · Normalization · Connectors · Analysis · Cameras · Matching health · Errors · Users). It exists so the console can be seen without installing DeCAR. It opens from a file:// URL, needs no server and no build step, and has no external references of any kind — no fonts, no scripts, no images, no requests.

What it is not

It is not the product, and it is not connected to one. The detections, cameras, people, plates, connectors and version numbers are invented. The interactions are real — filtering, correcting, disassociating, threshold editing and installing all behave as designed — but they operate on the sample data in this file and are lost on reload.
